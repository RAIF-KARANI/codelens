# The demo API on Vercel

This folder is the **root directory of the Vercel project for the demo's API**
(`docs/demo.md`). It holds no code of its own:

| File | What it's for |
|---|---|
| `main.py` | Vercel's entrypoint: imports the FastAPI `app` from `services/api`, with JSON logs by default (`LOG_FORMAT`, D121) |
| `pyproject.toml`, `uv.lock` | A small uv project of its own: it depends on `../../services/api` by path (which brings `packages/core`), and pins every other package, as constraints, to the workspace's `uv.lock`. Both generated by `scripts/export_demo_requirements.py` (CI checks they're current); Vercel installs them with `uv sync --frozen` |
| `.python-version` | Python 3.12, as the project |
| `vercel.json` | The function region (Mumbai), and a daily cron calling `/health`: it touches the database, which keeps a free Supabase project from pausing after a week idle |

## Vercel project settings

| Setting | Value |
|---|---|
| Root Directory | `deploy/api` |
| Include files outside the root directory in the Build Step | **on** (the default): the project installs `../../services/api` and `../../packages/core` |
| Framework Preset | FastAPI (detected) |
| Function region | set in `vercel.json` (`regions`): Mumbai `bom1`, next to the Supabase project (`ap-south-1`), since every page makes several database queries. Without it the function ran in Washington (`iad1`), and each new database connection took 1.2 s |

Environment variables:

| Name | Value |
|---|---|
| `DEMO_MODE` | `true` |
| `DATABASE_URL` | Supabase's **Transaction pooler** connection string (port 6543), as `postgresql+asyncpg://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:6543/postgres?ssl=require` |
| `DATABASE_TRANSACTION_POOLER` | `true`: asyncpg's prepared-statement caches off, which a transaction-mode pooler needs (`docs/demo.md` §5) |
| `API_JWT_SECRET` | the demo's own secret (`.env.demo`), the same value as the dashboard's |

No Redis, GitHub or model settings: a demo runs on Postgres alone.

**Scope `DATABASE_URL` and `API_JWT_SECRET` to Production only, and keep Git Fork
Protection on** (Settings → Git). Vercel builds a Preview of every branch and pull request,
running that branch's code (this project installs `services/api` and `packages/core` from
it), and adding a variable ticks every environment by default. A Preview that got
`DATABASE_URL` would hand the demo database's owner password to a pull request's code,
which could write to the database directly, past the API's read-only mode (security audit
run-2, D192).

## Checked locally

A fresh Python 3.12 environment from `uv sync --frozen --no-dev --no-editable` in this
folder, with uv 0.10.11 (the version Vercel's build used), installed both local
packages as real copies (53 MB, against Vercel's 500 MB limit) and served `main:app`
with `DEMO_MODE=true`: 401 without a token. Earlier, against Supabase, `/health` and
every page answered with a visitor token.

**Why not a `requirements.txt`** (the first try, 2026-10-15): Vercel turns one into a
`pyproject.toml`, rebasing `../../packages/core` to the repository root
(`packages/core`) but writing the file into this folder, so its build looked for
`deploy/api/packages/core` and failed ("Distribution not found"). A `pyproject.toml`
of our own is used as it is.
